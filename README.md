# Nexora — Smart choices. Better technology.

Повнофункціональний інтернет-магазин сучасної комп'ютерної периферії (клавіатури, мишки, навушники, вебкамери). Проєкт розроблено в рамках курсу **«Об'єктно-орієнтоване програмування» (ООП)** для демонстрації практичного застосування фундаментальних принципів об'єктно-орієнтованого дизайну, шаблонів проєктування, типізації, клієнт-серверної архітектури REST API та безпеки доступу на основі ролей (RBAC).

## Технологічний стек

- **Бекенд:**
  - **Python 3.14** (сумісно з Python 3.11+).
  - **FastAPI 0.162.5** — асинхронний веб-фреймворк для створення REST API з автоматичною OpenAPI (Swagger) документацією.
  - **Uvicorn 0.54.0** — високопродуктивний ASGI-сервер.
  - **Pydantic v2** — валідація вхідних даних та типізація запитів.
  - **SQLite3** — реляційна база даних (вбудований модуль `sqlite3`).
  - **PyJWT 2.15.1** — генерація та верифікація JSON Web Tokens (HS256).
  - **pwdlib 0.3.1 (Argon2id)** — криптографічне хешування паролів.
  - **python-dotenv** — завантаження змінних середовища з файлу `.env`.
- **Фронтенд:**
  - Чистий **Vanilla JavaScript (ES6+)**, **HTML5**, **CSS3** (без важких сторонніх бібліотек чи фреймворків).
  - Односторінковий застосунок (SPA) з клієнтською маршрутизацією між розділами.
  - Адаптивний та чуйний інтерфейс у фірмовому стилі Nexora.
- **Тестування:**
  - Вбудований фреймворк Python **`unittest`** (101 тест, включно з модульними, інтеграційними та тестами безпеки).

## Системні вимоги та встановлення

### Передумови
- Встановлений інтерпретатор **Python 3.14** (або версії 3.11–3.13).
- Встановлений веб-браузер (Google Chrome, Firefox, Edge).
- Командна оболонка (у прикладах нижче використовується **Windows PowerShell**).

### 1. Клонування репозиторію та перехід у папку проєкту
```powershell
cd oop-tech-store
```

### 2. Створення та активація віртуального оточення
```powershell
# Створення віртуального оточення .venv
python -m venv .venv

# Активація віртуального оточення у Windows PowerShell
.\.venv\Scripts\Activate.ps1
```
*(Якщо виконання скриптів заблоковано політикою ExecutionPolicy, можна використати прямий виклик `.\.venv\Scripts\python.exe` або тимчасово дозволити виконання: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`).*

### 3. Встановлення залежностей
```powershell
pip install -r requirements.txt
```

## База даних: робочий та тестовий режими

У проєкті реалізовано надійний **вбудований захисний механізм бази даних (Database Safety Guard)** (`src/services/database.py`).

| Режим | Змінні середовища | Цільовий файл БД | Призначення |
| :--- | :--- | :--- | :--- |
| **Production (за замовчуванням)** | Не потрібні (або відсутні) | `db.sqlite3` | Робоча база даних для роботи інтернет-магазину та збереження реальних замовлень. |
| **Test (тестовий)** | `NEXORA_ENV=test`<br>`NEXORA_DB_PATH=db.test.sqlite3` | `db.test.sqlite3` | Ізольована копія для виконання тестів, перевірок та ручного тестування. |

### Захисні правила:
1. Якщо `NEXORA_ENV=test`, застосунок **обов'язково вимагає** явно заданої змінної `NEXORA_DB_PATH`.
2. Якщо в тестовому режимі `NEXORA_DB_PATH` вказує на робочий файл `db.sqlite3`, сервер **відмовляється запускатися** з помилкою `DatabaseConfigurationError`. Робоча база даних ніколи не перезаписується під час тестування.
3. База даних автоматично ініціалізує таблиці (`users`, `products`, `orders`, `order_items`) та наповнює каталог початковими 8 товарами, якщо таблиця товарів порожня.

## Запуск бекенду та фронтенду

Для повноцінної роботи магазину відкриваються два окремих термінали: один для REST API (порт 8000), другий для веб-інтерфейсу (порт 5501).

### Крок 1. Запуск бекенду FastAPI (Термінал 1)

**У робочому режимі:**
```powershell
cd oop-tech-store
.\.venv\Scripts\uvicorn src.api.main:app --host 127.0.0.1 --port 8000
```

**Або в ізольованому тестовому режимі:**
```powershell
cd oop-tech-store
$env:PYTHONPATH="."
$env:NEXORA_ENV="test"
$env:NEXORA_DB_PATH="db.test.sqlite3"
.\.venv\Scripts\uvicorn src.api.main:app --host 127.0.0.1 --port 8000
```

- **Swagger UI (інтерактивна документація):** [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- **ReDoc:** [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)
- **Перевірка працездатності (Health Check):** [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)

### Крок 2. Запуск фронтенду (Термінал 2)

Фронтенд запускається за допомогою вбудованого HTTP-сервера Python на порту `5501` (порт дозволений у налаштуваннях CORS бекенду):

```powershell
cd oop-tech-store
.\.venv\Scripts\python.exe -m http.server 5501 --directory src/web
```

Після запуску відкрийте інтернет-магазин у браузері:  
👉 **[http://127.0.0.1:5501](http://127.0.0.1:5501)**

## Керування обліковими записами адміністратора

З міркувань безпеки публічна реєстрація на сайті (`POST /auth/register`) **завжди** створює облікові записи виключно з роллю покупця (`Customer`). Надати права адміністратора через браузер неможливо.

Створення облікових записів адміністратора (`Admin`) здійснюється за допомогою авторизованих локальних CLI-команд у терміналі сервера:

### 1. Початкове створення першого адміністратора (Bootstrap)
Використовується, коли в системі ще немає жодного адміністратора:
```powershell
cd oop-tech-store
$env:PYTHONPATH="."
.\.venv\Scripts\python.exe -m src.scripts.bootstrap_admin
```
*(Для тестової бази додайте перед запуском: `$env:NEXORA_ENV="test"`; `$env:NEXORA_DB_PATH="db.test.sqlite3"`).*

### 2. Створення додаткових адміністраторів
Якщо перший адміністратор уже існує, створення додаткового акаунта виконується командою:
```powershell
cd oop-tech-store
$env:PYTHONPATH="."
.\.venv\Scripts\python.exe -m src.scripts.create_admin
```

### Особливості CLI-інструментів:
- Запитують ім'я, робочу електронну пошту, пароль та підтвердження пароля.
- Введення пароля здійснюється приховано (`getpass` без відображення символів у консолі).
- Валідують довжину пароля (щонайменше 8 символів) та коректність email.
- Забороняють використання email, який уже зареєстрований покупцем (`Customer`), що унеможливлює несанкціоноване підвищення привілеїв.
- Після створення адміністратор входить на сайті через звичайну вкладку **«Вхід»** у розділі **«Особистий кабінет»**. Після авторизації в навігаційній панелі автоматично стають доступними кнопки **«Керування товарами»** та **«Керування замовленнями»**.

## Автоматизоване тестування

Проєкт містить повний набір з **101 автоматизованого тесту**, які перевіряють усі компоненти системи.

> **Важливе правило:** Тести завжди запускаються в тестовому режимі з використанням тестової або тимчасової бази даних. Запуск тестів на робочій базі `db.sqlite3` суворо заборонений.

### Команда запуску всіх 101 тестів:
```powershell
cd oop-tech-store
$env:PYTHONPATH="."
$env:NEXORA_ENV="test"
$env:NEXORA_DB_PATH="db.test.sqlite3"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

### Очікуваний результат:
```text
Ran 101 tests in ~5s
OK
```

### Склад тестових наборів:
1. `tests/test_models.py` — юніт-тести моделей `Product`, `CartItem`, `Cart`, `OrderItem`, `Order`.
2. `tests/test_orders.py` — тести бізнес-правил замовлень, ієрархій оплати (`CardPayment`, `CashPayment`), доставки (`CourierDelivery`, `PickupDelivery`), розрахунку вартості та списання товарів.
3. `tests/test_product_service.py` — тести фабрики `ProductFactory`, сервісу товарів, поліморфізму описів та фільтрації.
4. `tests/test_database_products.py` — тести роботи з SQLite, цілісності даних та захисного механізму режимів бази даних (`TestDatabaseSafetyGuard`).
5. `tests/test_user_service.py` — тести сервісу користувачів, створення токенів, перевірки підписів JWT та CLI-скриптів створення адміністраторів.
6. `tests/test_api_products.py` — тести ендпоінтів REST API, перевірка блокування доступу покупців до панелі керування (код 403) та валідація схем.

## Реалізація принципів ООП у проєкті

Проєкт побудовано з суворим дотриманням класичних принципів об'єктно-орієнтованого програмування:

### 1. Інкапсуляція (Encapsulation)
- Усі критичні атрибути доменних об'єктів приховані за допомогою приватних полів (подвійне підкреслення `__`):
  - `Product`: `__product_id`, `__name`, `__brand`, `__price`, `__stock_quantity` ([`src/models/product.py`](src/models/product.py)).
  - `User`: `__user_id`, `__name`, `__email` ([`src/models/user.py`](src/models/user.py)).
  - `CartItem` / `Cart`: `__product`, `__quantity`, `__items` ([`src/models/cart.py`](src/models/cart.py)).
  - `Order`: `__order_id`, `__items`, `__delivery`, `__payment`, `__status` ([`src/models/order.py`](src/models/order.py)).
- Доступ до стану та зміна полів здійснюються виключно через публічні методи з обов'язковою бізнес-валідацією (наприклад, заборона встановлення від'ємної ціни чи залишку).

### 2. Абстракція (Abstraction)
- Використано модуль `abc` для оголошення абстрактних базових класів з абстрактними методами (`@abstractmethod`), які визначають контракт поведінки для всієї ієрархії:
  - `Product(ABC)` -> обов'язковий метод `get_description(self) -> str` ([`src/models/product.py`](src/models/product.py)).
  - `User(ABC)` -> обов'язковий метод `get_role(self) -> str` ([`src/models/user.py`](src/models/user.py)).
  - `Delivery(ABC)` -> методи `calculate_cost(self) -> float`, `estimate_delivery_time(self) -> str` ([`src/models/delivery.py`](src/models/delivery.py)).
  - `Payment(ABC)` -> методи `process_payment(self) -> str`, `refund(self) -> str` ([`src/models/payment.py`](src/models/payment.py)).

### 3. Успадкування (Inheritance)
- Спеціалізовані класи розширюють функціонал абстрактних предків, перевикористовуючи базовий конструктор через `super().__init__()`:
  - `Keyboard`, `Mouse`, `Headphones`, `Webcam` успадковують `Product`, додаючи специфічні поля (тип перемикачів, DPI, бездротовий режим, FPS).
  - `Customer` та `Admin` успадковують `User`, розділяючи можливості покупця (історія замовлень, список бажань) та адміністратора.
  - `CourierDelivery` та `PickupDelivery` успадковують `Delivery`.
  - `CardPayment` та `CashPayment` успадковують `Payment`.

### 4. Поліморфізм (Polymorphism)
- Однаковий виклик методу на екземплярах різних підкласів призводить до специфічної для підкласу поведінки без необхідності перевірки типів (`isinstance`):
  - Метод `get_description()` поліморфно генерує структурований опис: для клавіатури формується інформація про свічі та розкладку, для мишки — DPI та тип з'єднання, для вебкамери — роздільна здатність та FPS.
  - Метод `calculate_cost()` поліморфно повертає `0.0` для самовивозу та розраховує тариф `80 + 15 * km` для кур'єрської доставки.
  - Метод `process_payment()` поліморфно формує чек оплати карткою або готівкою.

### 5. Шаблони проєктування та узагальнення (Design Patterns & Generics)
- **Фабричний метод (Factory Method):** Клас `ProductFactory` ([`src/services/product_factory.py`](src/services/product_factory.py)) інкапсулює валідацію вхідних даних та динамічне створення відповідного підкласу товару на основі рядка категорії.
- **Generic Repository:** Клас `Repository[T]` ([`src/services/repository.py`](src/services/repository.py)) реалізує узагальнене сховище колекцій об'єктів будь-якого типу з методами додавання, пошуку та видалення.

## Функціональні можливості магазину

1. **Каталог товарів:**
   - Відображення карток з фотографіями, цінами, статусом наявності та автоматично згенерованими характеристиками.
   - Перемикання режиму відображення: сітка (Grid) / список (List).
2. **Фільтрація та пошук:**
   - Фільтрація за 4 категоріями товарів.
   - Слайдер максимальної ціни (0 — 10 000 грн) з динамічним оновленням лічильника.
   - Множинний вибір виробників (чекбокси брендів: Logitech, Razer, HyperX тощо).
   - Повнотекстовий пошук за назвою та брендом у реальному часі.
   - Сортування за ціною (зростання / спадання) та назвою.
3. **Кошик покупця:**
   - Додавання товару з каталогу з плавною анімацією Toast-повідомлення (*«Товар додано до кошика»*).
   - Зміна кількості одиниць товару з миттєвим перерахунком суми та контролем залишків.
   - Збереження стану кошика в `localStorage`.
4. **Оформлення замовлення (Checkout):**
   - Підтримка замовлень як для авторизованих користувачів, так і для гостей.
   - Вибір способів доставки: Самовивіз (безкоштовно) або Кур'єр (з розрахунком відстані та вартості).
   - Вибір способів оплати: Банківська картка або Готівка при отриманні.
   - Автоматичне списання залишків товару на складі після успішного оформлення.
5. **Особистий кабінет:**
   - Безпечна реєстрація та авторизація через JWT.
   - Перегляд профілю та історії власних замовлень користувача.
6. **Панель керування адміністратора:**
   - **Керування товарами:** перегляд усього асортименту, додавання нового товару, редагування існуючого (ціна, залишок, опис, характеристики), видалення товару.
   - **Керування замовленнями:** перегляд усіх замовлень (покупців і гостей), перегляд детального складу замовлення, оновлення статусів (Нове -> Підтверджено -> Відправлено -> Виконано -> Скасовано).
   - При скасуванні замовлення товари автоматично повертаються на склад магазину.
